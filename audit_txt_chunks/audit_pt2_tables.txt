> **Table 1 Methodological Notes and Technical Specifications:**  
> `*` **N/A\*** (*PMU Instruction Counters on Windows*): In Windows user-mode, CPU PMU architectural instruction counters are restricted by the NT kernel without elevated driver tracing (kernel ETW/WPR profiling introduces asynchronous latency unsuited to isolated process measurement). Win32 user-mode API exposes thread cycles via `QueryProcessCycleTime` (`realtimeapiset.h`), precluding access to `IA32_FIXED_CTR0` (`INST_RETIRED.ANY`). Synthetic IPC extrapolations are avoided; CPU cycles are reported directly (45.8M cycles in PicoClaw vs. 528.1M cycles in OpenClaw Full on Windows 11 NVIDIA, a 11.54x ratio). *References & Technical Documentation:* Weaver et al. (IEEE ISPASS 2013); Microsoft Learn (`QueryProcessCycleTime`); Intel 64 and IA-32 SDM Vol. 3B Ch. 20.  
> `§` **N/A§** (*Peak RSS of PythonNative on Windows — unified with Fig. 2(b) and Table 8*): Windows invocation via `py.exe` (PEP 397) acts as a lightweight launcher wrapper stub dispatching an independent worker child process (`python.exe`). PSAPI telemetry (`GetProcessMemoryInfo`) monitored the parent wrapper PID (~4.91 MB) rather than the CPython worker heap; `N/A§` is reported uniformly instead of the wrapper stub figure. *Technical Documentation:* Python PEP 397; Microsoft Learn (Win32 PSAPI).  
> `‡` **N/A‡** (*Direct Neural Baseline*): The neural baseline issues direct HTTP requests from the telemetry harness to the resident `llama-server` without intermediary agent runtimes ($T_{\text{orch}} \equiv 0$); no client agent process exists for RSS or instruction attribution.  
> `||` **N/A||** (*Bun JSC on macOS*): Bun (JSC) was evaluated as a secondary JavaScript engine ablation on x86_64 nodes (Linux and Windows) following the completion of the Darwin ARM64 reference campaign.  
> `**` **N/A\*\*** (*Host Package Energy on Windows Intel Graphics*): Intel HD Graphics 4600 operates on unified host memory aperture (UMA); without a kernel RAPL MSR driver or discrete NVML, host package energy and EDP are not instrumented in unprivileged user-mode.  
> **Note — Cross-ISA Hardware Counter Segregation:** Direct numerical comparisons of retired hardware instruction counts between Apple Silicon (ARM64 RISC) and Intel Core (x86_64 CISC) are microarchitecturally incommensurable due to divergent instruction densities, macro-op fusion, and RISC micro-operation expansion; evaluate hardware instructions via within-ISA relative ratios (e.g., OpenClaw Full vs. PicoClaw).  
> **Note — Clean Physical Executions:** All consolidated datasets originate from unbroken, from-scratch executions without partial or reused trials.

> **Table 2 Methodological Notes on Statistical Inference, $r_1$ Variance Adjustment, and W5 Exclusion:**
> - **Positive-Autocorrelation Variance Adjustment (M4):** Standard Mann-Whitney $U$ assumes i.i.d. observations ($n=30$). For cells exhibiting positive lag-1 autocorrelation ($r_1 > 0$), effective sample size $n_{\text{eff}} = n(1-r_1)/(1+r_1)$ is used to inflate the asymptotic variance of $U$ by $\text{VIF} = [(n_{\text{eff},1}+n_{\text{eff},2}+1)/(n_{\text{eff},1} n_{\text{eff},2})] / [(n_1+n_2+1)/(n_1 n_2)]$ (for $r_1 \le 0$, $n_{\text{eff}} = n$ is retained conservatively). Across 146 contrasts, **99** are significant under standard Holm-Bonferroni and **93** remain significant under $r_1$-corrected Holm-Bonferroni; **6** contrast(s) marked `(NS*)` lose significance after accounting for positive autocorrelation.
> - **Workload W5 Segregation (M1):** `python_native` (LangChain Core) in W5 is excluded from all pairwise latency/performance contrasts in Table 2 due to schema validation failure and confounded prompt truncation (see Table 8 and `w5_token_and_schema_audit.csv`).
> - **Multiple Testing Correction:** Family-wise error rate across all pairwise hypothesis tests is controlled via the Holm-Bonferroni step-down procedure (Holm 1979) applied separately to standard and $r_1$-adjusted $p$-values.

> - **(a) Estimator:** Difference of session medians $\hat{\theta} = \text{median}(c_2) - \text{median}(c_1)$ evaluated against a fixed, pre-specified data-independent SESOI of $\Delta_{\text{SESOI}} = \pm 5.0\text{ ms}$ (practical orchestration jitter bound, $<0.2\%$ of Regime A task duration).
> - **(b) Deviation Unit:** Per-trial paired orchestrator contrasts $c_i = T_{\text{orch}, i}(\text{Runtime}) - T_{\text{orch}, i}(\text{PicoClaw})$ ($n=30$ per session) resampled in contiguous overlapping blocks via Moving Block Bootstrap ($B=10{,}000$ resamples; Künsch 1989) to preserve serial dependence without distorting per-trial median dispersion.
> - **(c) Block-Size Rule:** Primary block size $b = \text{round}(n^{1/3}) = 3$ for $n=30$ trials per session.
> - **(d) Block-Size Sensitivity ($b \in \{2, 3, 5\}$, exported in `audit_export/tost_block_sensitivity.csv`):** Under Holm-Bonferroni FWER control ($p_{\text{TOST, adj}} < 0.05$), all three block lengths yield identical decisions across the 95 valid pairs: $b=2$: **71 `Equivalent` / 24 `Inconclusive` / 0 `Different`** (unadjusted: 76/19/0); $b=3$: **71 / 24 / 0** (unadjusted: 76/19/0); $b=5$: **71 / 24 / 0** (unadjusted: 78/17/0).
> - **Three-State Decision Rule (Schuirmann 1987; Lakens 2017) + Multiple-Comparison Control:** Order-statistic **90% MBB CIs** align with one-sided $\alpha = 0.05$ TOST, combined with Holm-Bonferroni FWER adjustment across all 95 valid pairs (7 confounded W5 `python_native` pairs excluded per M1): `Equivalent` (90% CI entirely inside $[-5.0, +5.0]\text{ ms}$ and $p_{\text{TOST, adj}} < 0.05$: **71 [74.7%]**), `Different` (90% CI wholly outside $[-5.0, +5.0]\text{ ms}$: **0 [0.0%]**), or `Inconclusive` (**24 [25.3%]**, comprising 19 pairs whose 90% CI crosses $\pm 5.0\text{ ms}$ plus 5 pairs failing the Holm-Bonferroni adjusted threshold).
